# B03 homepage: implementation and contracts

## Scope and flow

HomePage is now the public / route. It composes HeroSection, HowItWorks, ScoreDemo, PrizePoolPreview and FeaturedCharities, followed by a final membership invitation and a mobile subscribe dock. Components reuse B02's buttons, cards, badges, feedback, header, footer and token system. The prior foundation page remains available at /foundation; member/admin and UI-library routes remain intact.

Homepage links navigate to /register, /charities and /how-it-works. Registration and the live charity directory are prerequisites owned by later branches. Their availability pages explicitly state that accounts, payments and donations cannot be submitted here. They expose no fake form or success path. /how-it-works is a complete explanation page, including real in-page navigation to #draw-rules. Cause-card links navigate to the corresponding illustrative category on /charities. RouteFocus now handles both pathname and hash changes, focuses valid section IDs and safely falls back to main for missing/malformed fragments.

The homepage has no API calls or live totals. Its imported examples are UI-only data. ScoreDemo compares fixed arrays locally and updates a labelled result when a user selects 3, 4 or 5 matches. The charity list accepts a documented external-data contract for future wiring; it handles loading, errors, empty lists, invalid records and image failures without claiming successful data loading.

## Product rules and example boundaries

- At least 10% of a subscription goes to the selected charity; a user may choose more. The separate independent donation option does not buy a draw entry and is not implemented in B03.
- Participation requires active membership and five recorded scores. Scores use the 1–45 range, with one score per date and the latest five retained. The homepage calls them recorded scores, not single-hole scores.
- Three matches share 25% of the pool, four share 35%, five share 40%. Each tier is divided equally among its winners. Only the five-match jackpot can roll over. Verification precedes payout; nothing promises instant disbursement.
- The £10,000 example (GBP) yields illustrative tier allocations of £2,500 / £3,500 / £4,000. It is not a live total, individual guaranteed win, subscription price, configured product currency or prize-contribution rate. No membership price is invented.
- The comparison examples use five distinct values to avoid silently deciding the unresolved duplicate-score policy. They are not the draw engine or an eligibility decision.
- Cause cards are explicitly illustrative categories, not named/verified partners, donor records or real grants. No impact totals, winner stories, draw dates, certification, WHS integration, escrow promises or audit claims were copied from the export.

## Charity-card integration contract

The future API adapter must map its response into this view contract before rendering. FeaturedCharities is a view, not an API client. It currently supports status=loading, error and ready. A ready empty array shows an empty state. A malformed ready response shows an error rather than partially showing misleading records.

```js
{
  id: 'stable-unique-id',
  name: 'Display name',
  category: 'Cause category',
  description: 'Plain-text summary',
  image: { src: '/assets/image.jpg', alt: 'Meaningful image description' },
  href: '/charities/stable-slug',
  isExample: false
}
```

id, name, category, description, href and both image fields are required nonblank strings. id must be unique within the array. href must start with /charities followed by a path/query/hash boundary and contain no backslash. Image sources must be root-relative or HTTP(S). isExample is always explicit. In B03 the actual links point to implemented /charities#category sections; individual live /charities/:slug routes are not implemented yet and must be wired with the future directory. Do not pass individual record paths until those routes exist.

## Design assets and responsiveness

The mobile homepage PNG/HTML and responsive-shell references informed the layout; the B02 DESIGN.md tokens remain the source of palette and geometry. home.css scopes the new sections and adds desktop two-column hero/comparison layouts, mobile stacked steps, score circles, forest prize card and a safe-area subscribe dock. It uses 48px or larger action targets, visible text with matched-number ticks, and existing focus styles. Motion is a short entry animation only; prefers-reduced-motion disables it. Focus scrolling leaves clearance for the mobile dock.

Four images were copied unchanged from the supplied homepage export and bundled locally. SOURCES.md records each original URL. The hero source contains screenshot chrome outside the photographed region; CSS object-fit crops the presentation to the photograph without modifying the asset. Source images are modest resolution and should be replaced with approved high-resolution assets for production. Their captions do not claim real participants or partners.

B02 inherited formatting in Modal.jsx and index.css was normalized only; no behavioral changes were made there.
